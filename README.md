# Getsumen — 月面ロボットシミュレータ

有人与圧ローバーが HLS（有人着陸機）に接近するオペレーションを検討するための、Python ベースの月面シミュレーションです。
起動するとブラウザから見られます。

```
左上: ライダーの点群 (車両上方から)      右: 月面の3D
左下: カメラ画像 (前 / 左右 / 後ろ左右)
```

## 起動

```bash
pip install -r requirements.txt
python server.py                          # 既定の設定 (config/default.yaml)
python server.py -c my.yaml --port 9000 --seed 3
```

ブラウザで http://localhost:8080/ を開きます。three.js は `web/vendor/` に同梱しているのでオフラインでも動きます。
テストは `python -m unittest discover -s tests` です。

## 操作

| 操作 | 内容 |
|---|---|
| W / S（↑ / ↓） | 前進 / 後退（押している間だけ走行） |
| A / D（← / →） | 左 / 右旋回 |
| Shift / Space | 低速 / 停止 |
| R | 初期位置へリセット |
| V / ドラッグ / ホイール | 視点切替（追従・俯瞰） / 回転 / ズーム |
| 点群ビューでホイール | 表示半径の変更 |
| 明るさスライダ | 右の3Dビューの明るさ（カメラ画像には影響しません） |
| 太陽方位 / 仰角スライダ | 太陽方向を変更（地形の影をサーバで再計算、1〜2秒） |

キー入力は、スライダやボタンにフォーカスがあっても効きます。HLS とは衝突して止まります（円柱の外側へは入れません）。

## 設定

既定値はすべて `config/default.yaml` にあります（コメントつき）。`-c my.yaml` で渡したファイルは、**既定への差分**として上書きされます。変えたい項目だけ書けば足ります。
カメラ/ライダーのリストは、書くと丸ごと置き換わります。各項目には `camera_defaults` / `lidar_defaults` の既定値が適用されます。変更後は再起動してください。

```yaml
# my.yaml の例
world: {seed: 3, sun: {elevation_deg: 1.0}}
rover: {color: "#ffcc00"}
sensors:
  camera_defaults: {rate_hz: 1}          # 全カメラの更新レート
  lidars:
    - name: front_flash
      mount: {x: 3.0, y: 0.0, z: 0.7, yaw_deg: 0, pitch_deg: -20}   # 俯角20°
      h_fov_deg: 40
      v_fov_deg: 30
      h_pixels: 128
      v_pixels: 96
      max_range: 60
```

| 項目 | 内容 |
|---|---|
| `world` | 地形シード、クレータの量と大きさ、起伏、太陽（方位・仰角・影の中の明るさ） |
| `hls` / `rover` | HLS（円柱）とローバー（箱）の位置・寸法・色、ローバーの性能 |
| `sensors.cameras` | 取付位置・向き（`mount`）、画角・解像度・更新レート、センサ特性、画面上の配置（`grid`） |
| `sensors.lidars` | 取付位置・向き、視野、画素数、距離範囲、ノイズ、反射率 |
| `ui` | 点群ビューの表示半径、3Dビューの明るさ・補助光、カメラ画像の列数 |

座標は車体座標（x=前 / y=左 / z=上）です。`mount.yaw_deg` は左向きが正、`mount.pitch_deg` は上向きが正です。

## 構成

```
server.py                Python 側のすべて (下の「server.py の構成」)
config/default.yaml      設定の既定値 (唯一の置き場)
web/
  app.js                 ブラウザ側のすべて (3Dビュー, カメラ画像のセンサ処理, 点群, キー操作, 通信)
  index.html, style.css
tests/test_world.py
```

`server.py` は、上から順に次の9つの部分で構成されています（見出しコメントで区切ってあります）。

1. 設定: 既定 + 指定ファイル（差分）の読み込み
2. 座標系: 車体座標・世界座標と回転
3. 月面: 高さマップ（起伏 + クレータ）、太陽の影、レイキャスト（`World`）
4. ローバー: ユニサイクル運動 + 4点接地による姿勢追従、HLS 衝突停止（`Rover`）
5. ライダー: フラッシュライダー（`FlashLidar`）
6. カメラ画像: レイトレーシング（`RayTracer`）
7. ワーカー: 重い計算（レイトレ / ライダー / 影の再計算）を別プロセスで実行
8. サーバ: aiohttp + WebSocket（状態 JSON、点群・カメラ画像バイナリ）、静的ファイル
9. 起動: コマンドライン引数

### データの流れ
1. 起動時に `World` が高さマップを生成します（シード固定）。ワーカープロセスも同じ設定から同じ世界を再生成するので、地形データは転送しません。
2. ブラウザは `/api/world`（設定）、`/api/heightmap`（高さ）、`/api/shade`（地形の影）を取得して3Dビューを組み立てます。
3. WebSocket でローバーの状態（30 Hz）、ライダーの点群、レイトレ済みのカメラ画像（HDR float16）を受け取ります。操作と太陽の変更は、ブラウザからサーバへ送ります。

## 月面の作り方（`server.py` の `World`）
実際の地形データ（DEM）ではなく、**月南極（極域ハイランド）の公開統計を模した合成地形**です。同じ `seed` なら同じ地形になります。

- **起伏**: ホワイトノイズを FFT で 1/f^β に整えます。長波長側は `wavelength` で打ち切り、振幅は `amplitude` です。細かい凹凸は別に足します。
- **クレータ**: 累積サイズ頻度 N(>D) = 1.54·sat·D⁻²（傾き -2、平衡状態）に従い、直径 4〜80 m を重ねます。深さ/直径は劣化度でばらつきます。断面は放物面の窪みに、なだらかなリムを足した形です。
- **平坦化**: HLS のパッドと地形の端は平らにします。地形の外側は z=0 の平面として扱います。
- **太陽と影**: 南極では仰角が 0〜約1.5° なので、影が非常に長くなります（20 m の HLS で約760 m）。
  地形自身の影は、各セルから太陽方向へ走査したホライズンで焼き込みます（太陽の視直径による半影つき）。HLS・ローバーの影は影レイで求めます。

ライダー、カメラ画像、ローバーの接地、ブラウザの3Dビューは、すべて同じ高さマップ・HLS を使います。

## センサ

### ライダー
各画素の方向へレイキャストして、距離を点群にします。画素は平面の検出器上に等間隔に並ぶ（カメラと同じ平面投影）ので、平らな地面では、最遠の行は直線に、左右の端も直線になります。点群を上から見ると、遠いほど広がる台形（扇形）になります（`test_lidar_footprint_on_flat_ground_is_a_trapezoid`）。

- **届く範囲**: 俯角と縦視野で決まります。視野の上端が水平より下なら、地面に当たる距離は 「センサ高 / tan(俯角)」までです。例: センサ高 1.3 m・俯角 -20°・縦視野 30° では、上端が -5° なので約 15 m までです。点群ビューの黄色い扇形が、この範囲（平坦な地面を仮定した概算）です。
- **検出限界**: 受信強度が 反射率 × cos(入射角) / 距離² に比例するので、`max_range` は「基準反射率の面に垂直入射したとき」の距離として扱います。地面すれすれや暗い面は、それより手前で検出できなくなります。HLS（白色）は遠くまで届きます。

### カメラ画像
サーバ側（numpy）で画素ごとに光線を飛ばして生成します（`RayTracer`）。ブラウザは、その結果にセンサ処理を加えて表示します。

- **一次光線**: 地形（マーチング + 二分法）、HLS（円柱の側面と上面）。
- **影レイ**: 地形は焼き込み済みの影、HLS・ローバーは解析的な影レイ、HLS の表面には地形へのマーチング影レイを使います。
- **反射**: レゴリスは Lommel-Seeliger 則（太陽が低くても平地が真っ黒にならない）、HLS などの人工物は Lambert 反射です。太陽と反対側は直接光がゼロなので、ほぼ真っ黒です。
- **空**: 太陽円盤（放射輝度 約4.7×10⁴）と、等級ベースの恒星です。
- **センサ処理**（`web/app.js` の `Cameras`）: 自動露出 → 周辺減光 → ノイズ → トーンカーブ → sRGB、太陽が見えているときのグレア、地面距離の目盛（カメラ位置から平坦な地面を仮定した推定）。

星は、日向に合わせた通常の露出では見えません。0 等の星は、日向の地面の約10万分の1の明るさのためです。`exposure: 100000` 付近まで上げると微かに写ります。星の位置は合成カタログで、実在の星座ではありません。右の3Dビューの星は装飾です。

計算が重いので、既定は 320×240・2 Hz です（目安: 1 台あたり約 0.4 秒/コア）。CPU が足りないと `rate_hz` を下回ります。足りないときは `simulation.workers`（0 で CPU 数）、解像度、`rate_hz` を調整してください。

### 右の3Dビュー
ブラウザのリアルタイム描画です。見やすさのため、影の中の地形にだけ弱い補助光（`ui.view_fill`）を足し、HLS・ローバーには輪郭線を付けています。補助光と輪郭線はカメラ画像には影響しません。

## 簡略化している点（拡張候補）
- 特定地点の実 DEM（LOLA 5 m、LROC など）の読み込みは未実装です。`World.heights` を差し替えれば、他の部分はそのまま使えます。
- 永久影領域の暗さ、地球照、太陽の時間変化（約29.5日周期）の自動進行は未実装です。太陽方位はスライダで手動変更します。
- 地形の外側は平面で、遠方の地形や影はありません。
- HLS は円柱、ローバーは箱です（脚・エレベータ・車輪・轍は無し）。ローバーはキネマティクスのみです。
