# Getsumen — 月面ロボットシミュレータ

有人与圧ローバーが HLS（有人着陸機）に接近するオペレーションを検討するための、Python ベースの月面シミュレーション環境です。
起動するとブラウザから見られます。

```
左: LiDAR点群(車両上方から) + 前/後/左/右カメラ画像     右: 月面の3D(CG)ビュー
```

## 起動

```bash
pip install -r requirements.txt
python -m lunarsim                        # 既定: config/default.yaml
python -m lunarsim -c my.yaml --port 9000 --seed 3
```

ブラウザで http://localhost:8080/ を開きます。（three.js は `lunarsim/web/vendor/` に同梱しているのでオフラインでも動きます）

## 操作

| 操作 | 内容 |
|---|---|
| W / S（↑ / ↓） | 前進 / 後退 |
| A / D（← / →） | 左 / 右旋回 |
| Shift / Space | 低速 / 停止 |
| 自動アプローチ | HLS へ向けて自動走行し、設定した距離で停止 |
| V / ドラッグ / ホイール | 視点切替（追従・俯瞰） / 回転 / ズーム |
| R | 初期位置へリセット |
| 左上の LiDAR 図でホイール | 表示半径の変更 |
| 太陽方位 / 仰角スライダ | 太陽方向を変更（地形の影をサーバで再計算、1〜2秒） |

HUD には速度・HLS までの距離（車体前端〜HLS 表面）・HLS 方位・車体傾斜を表示します。

## 設定ファイル（`config/default.yaml`）

カメラとフラッシュライダーはすべて YAML で設定できます（変更後は再起動）。

```yaml
sensors:
  cameras:                  # 数・名称は自由。画面に自動で並びます
    - name: front
      mount: {x: 2.9, y: 0.0, z: 1.3, yaw_deg: 0, pitch_deg: -3}   # 車体座標 x前 y左 z上 / pitch は上向き正
      fov_deg: 90           # 水平画角
      width: 320
      height: 240
      rate_hz: 10
  lidars:
    - name: front_flash
      mount: {x: 3.0, y: 0.0, z: 0.7, yaw_deg: 0, pitch_deg: -6}
      h_fov_deg: 40         # 視野
      v_fov_deg: 30
      h_pixels: 128         # 画素数 (フラッシュライダーのアレイ)
      v_pixels: 96
      min_range: 0.5
      max_range: 60.0
      rate_hz: 5
      range_noise_std: 0.02 # 距離ノイズ σ [m]
      dropout: 0.01         # 欠測率
```

形状も設定で選べます。`hls.model: cylinder`（既定・単純な円柱）と `rover.model: box`（既定・単純な箱）は、寸法（`radius`/`height`、`length`/`width`/`height`/`clearance`）と `color` を指定できます。
`detailed` にすると、ノーズ・ハッチ付きの HLS と、キャビン＋6輪のローバーを描画します。
箱モデルでは、側面カメラを箱の表面（`y=±width/2`）に置いてください。

その他、`world`（地形シード・クレータ数/大きさ/深さ・岩の数/大きさ・太陽方位/仰角）、`hls`（位置・半径・高さ・ハッチ方向）、
`rover`（寸法・初期位置・最高速度・加速度・自動アプローチ停止距離）も調整できます。

## 構成

```
lunarsim/
  world.py   高さマップ(起伏+クレータ) / 岩 / HLS と レイキャスト
  lidar.py   フラッシュライダー (格子状レイ → 距離 → 点群)
  rover.py   ユニサイクル運動 + 4点接地による姿勢追従、HLS 衝突停止、自動アプローチ
  server.py  aiohttp + WebSocket (状態 JSON / 点群バイナリを配信)
  web/       three.js フロントエンド (CG・カメラ画像・点群ビュー)
config/default.yaml
tests/       python -m unittest discover -s tests
```

- **ライダー点群** は Python 側で計算します（高さマップのレイマーチング + 岩=球 + HLS=円筒の解析交差）。
  3D ビューの CG とは同一の地形データを使うので、点群と画像は整合します。
- **カメラ画像** はブラウザ側で同じシーンを車体取付位置から描画します（点群表示はカメラ画像には写りません）。
  ブラウザが GPU を使えない環境ではカメラ更新が遅くなります（`rate_hz` や解像度を下げてください）。

## 月南極の再現（公開統計ベース）

特定の実DEMは使わず、月南極（極域ハイランド）の公開統計に基づいて手続き的に生成します。同じ `seed` なら同じ地形です。

- **太陽**: 軸傾斜が約1.5°のため、仰角は 0〜約1.5° と地平線すれすれです（既定 方位110° / 仰角1.5°）。
  影が非常に長く（20 m の HLS で約760 m）、方位によっては接近経路が HLS や地形の影に入ります。
  スライダで変更すると、地形の影（太陽の視直径0.53°の半影つき）をサーバで再計算します。
  岩・HLS・ローバーの影はシャドウマップです。
- **クレータ**: 累積サイズ頻度 `N(>D)=1.54·sat·D⁻²`（傾き-2の平衡状態）で、直径4〜80 m が重なり合います。
  深さ/直径は劣化度でばらつきます。
- **岩**: 面積被覆率 k（極域の典型 1〜3%）と指数型サイズ分布（Golombek 型）に従い、一部を新しいクレータの縁に集中配置します。
- **反射**: Lommel-Seeliger 則を使います。Lambert では低い太陽の平地が真っ暗になりますが、レゴリスは地平線近くでも平地が見えます。
- **空**: 真っ黒な空で、大気による散乱はありません。太陽円盤は地形や HLS に隠れれば見えなくなります。

## カメラ画像（実機センサ風）

HDR（線形・浮動小数点）で描画してから、センサモデルを通します（`sensors.cameras[*]` で調整）。

1. **露出**: 自動露出（空は除外、日向の明部が飽和しすぎないようハイライト保護）か、固定倍率。`ev_bias` で補正できます。
2. **ノイズ**: 読み出し + ショットノイズ（`read_noise` / `shot_noise`）。影の中ほどノイズが目立ちます。
3. **周辺減光・光学ボケ**: `vignette` / `blur_px`。
4. **トーンカーブ → sRGB**。
5. **グレア**: 太陽が実際に見えている時だけ出ます（`glare`）。
6. **地面距離の目盛**: カメラ位置から、平坦な接地面を仮定した距離リング（既定 2〜50 m）を重ねます（`distance_overlay` / `overlay_distances`、画面の「距離目盛」で切替）。地形の凹凸の分だけ実距離とずれる推定値です。

右の3Dビューは見やすさのため、影の中にも補助光（`ui.view_fill`）を足しています。この補助光はカメラ画像には影響しません。

## 簡略化している点（今後の拡張候補）

- 特定地点の実DEM（LOLA 5 m・LROC SfS など）の読み込みは未実装です。GeoTIFFの取り込みを足せます。
- 永久影領域の暗さや地球照、太陽の時間変化（約29.5日周期）の自動進行は未実装です。方位はスライダで手動変更します。
- 地形外側は平面で、遠方の影はありません。
- HLS は円柱、ローバーは箱の簡易形状が既定です（`detailed` でも脚・エレベータは未モデル化。ハッチは描画のみ）。
- ローバーはキネマティクスのみです（スリップ・サスペンション動力学・轍は無し）。岩との衝突判定も無く、乗り越える扱いです。
