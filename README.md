# Getsumen — 月面ロボットシミュレータ

有人与圧ローバーが HLS（有人着陸機）に接近するオペレーションを検討するための、Python ベースの月面シミュレーション環境です。
起動するとブラウザから見られます。

```
左: LiDAR点群(車両上方から) + 前/後/左/右カメラ画像     右: 月面の3D(CG)ビュー
```

## 起動

```bash
pip install -r requirements.txt
python -m lunarsim                        # 既定: config/default.yaml
python -m lunarsim -c my.yaml --port 9000 --seed 3
```

ブラウザで http://localhost:8080/ を開きます。（three.js は `lunarsim/web/vendor/` に同梱しているのでオフラインでも動きます）

## 操作

| 操作 | 内容 |
|---|---|
| W / S（↑ / ↓） | 前進 / 後退（押している間だけ走行） |
| A / D（← / →） | 左 / 右旋回 |
| Shift / Space | 低速 / 停止 |
| 右下の操作パッド | 画面のボタンを押している間走行（キー押下も光って表示。マウス/タッチ用） |
| V / ドラッグ / ホイール | 視点切替（追従・俯瞰。画面にボタンは無くキーのみ） / 回転 / ズーム |
| R | 初期位置へリセット（画面にボタンは無くキーのみ） |

キー入力はスライダやボタンにフォーカスがあっても効きます（矢印キーでスライダが動くことはありません）。
| 左上の LiDAR 図でホイール | 表示半径の変更（点群のみ表示。HLSは描きません） |
| 明るさスライダ | 右の3Dビューの明るさ（カメラ画像には影響しません） |
| 太陽方位 / 仰角スライダ | 太陽方向を変更（地形の影をサーバで再計算、1〜2秒） |

HUD には速度・HLS までの距離（車体前端〜HLS 表面）・HLS 方位・車体傾斜を表示します。

## 設定ファイル（`config/default.yaml`）

カメラとフラッシュライダーはすべて YAML で設定できます（変更後は再起動）。
既定のカメラは 前・左・右・後ろ左・後ろ右 の5台で、画面では 前 / 左右 / 後ろ左右 の順に3段で表示します（各カメラの `grid: {row, col, span}` で配置、`ui.camera_grid_columns` で列数を指定）。

```yaml
sensors:
  cameras:                  # 数・名称は自由。画面に自動で並びます
    - name: front
      mount: {x: 2.9, y: 0.0, z: 1.3, yaw_deg: 0, pitch_deg: -3}   # 車体座標 x前 y左 z上 / pitch は上向き正
      fov_deg: 90           # 水平画角
      width: 320
      height: 240
      rate_hz: 10
  lidars:
    - name: front_flash
      mount: {x: 3.0, y: 0.0, z: 0.7, yaw_deg: 0, pitch_deg: -6}
      h_fov_deg: 40         # 視野
      v_fov_deg: 30
      h_pixels: 128         # 画素数 (フラッシュライダーのアレイ)
      v_pixels: 96
      min_range: 0.5
      max_range: 60.0
      rate_hz: 5
      range_noise_std: 0.02 # 距離ノイズ σ [m]
      dropout: 0.01         # 欠測率
      reference_reflectivity: 0.10  # max_range の基準反射率 (0 で下記の検出限界を無効化)
      ground_reflectivity: 0.12     # 月面の反射率
```

### ライダーの届く範囲
- **幾何**: `pitch_deg`（上向き正）と `v_fov_deg` で決まります。視野の上端が水平より下なら、地面に当たるのは センサ高 / tan(俯角) までです。
  例: センサ高 1.3 m、俯角 -20°、縦視野 30° では 上端が-5° なので 約 15 m までです（それより遠くは、より水平な光線が必要）。
  遠くを見たいなら俯角を浅く、近くだけなら深くするか縦視野を狭めます。
- **検出限界**: 受信強度は 反射率 × cos(入射角) / 距離² に比例するので、`max_range` は「基準反射率の面に垂直入射」での距離として扱います。
  地面すれすれ（入射角が大きい）や暗い面は、`max_range` よりずっと手前で検出できなくなります。HLS（白色）は遠くまで届きます。
- 点群ビューの黄色い扇形は、この地面到達範囲（平坦な地面を仮定した概算）で、下に「地面 近〜遠 m」を表示します。

形状も設定で選べます。`hls.model: cylinder`（既定・単純な円柱）と `rover.model: box`（既定・単純な箱）は、寸法（`radius`/`height`、`length`/`width`/`height`/`clearance`）と `color` を指定できます。
`detailed` にすると、ノーズ・ハッチ付きの HLS と、キャビン＋6輪のローバーを描画します。
箱モデルでは、側面カメラを箱の表面（`y=±width/2`）に置いてください。

その他、`world`（地形シード・クレータ数/大きさ/深さ・岩の数/大きさ・太陽方位/仰角）、`hls`（位置・半径・高さ・ハッチ方向）、
`rover`（寸法・初期位置・最高速度・加速度）も調整できます。

## 構成

```
lunarsim/
  world.py   高さマップ(起伏+クレータ) / 岩 / HLS と レイキャスト
  lidar.py   フラッシュライダー (格子状レイ → 距離 → 点群)
  rover.py   ユニサイクル運動 + 4点接地による姿勢追従、HLS 衝突停止
  raytrace.py カメラ画像のレイトレーシング (地形/岩/HLS, 影レイ, 太陽円盤, 恒星)
  workers.py  レイトレ/ライダー/影の再計算を別プロセスで実行
  server.py  aiohttp + WebSocket (状態 JSON / 点群・カメラ画像バイナリを配信)
  web/       three.js フロントエンド (CG・カメラ画像・点群ビュー)
config/default.yaml
tests/       python -m unittest discover -s tests
```

- **ライダー点群** は Python 側で計算します（高さマップのレイマーチング + 岩=球 + HLS=円筒の解析交差）。
  3D ビューの CG とは同一の地形データを使うので、点群と画像は整合します。
- **カメラ画像** は同じ地形データからサーバ側でレイトレーシングします（下記）。右の3Dビューはブラウザのリアルタイム描画（ラスタライズ）です。

## 月南極の再現（公開統計ベース）

特定の実DEMは使わず、月南極（極域ハイランド）の公開統計に基づいて手続き的に生成します。同じ `seed` なら同じ地形です。

- **太陽**: 軸傾斜が約1.5°のため、仰角は 0〜約1.5° と地平線すれすれです（既定 方位110° / 仰角1.5°）。
  影が非常に長く（20 m の HLS で約760 m）、方位によっては接近経路が HLS や地形の影に入ります。
  スライダで変更すると、地形の影（太陽の視直径0.53°の半影つき）をサーバで再計算します。
  岩・HLS・ローバーの影はシャドウマップです。
- **クレータ**: 累積サイズ頻度 `N(>D)=1.54·sat·D⁻²`（傾き-2の平衡状態）で、直径4〜80 m が重なり合います。
  深さ/直径は劣化度でばらつきます。
- **岩**: 面積被覆率 k（極域の典型 1〜3%）と指数型サイズ分布（Golombek 型）に従い、一部を新しいクレータの縁に集中配置します。
- **反射**: Lommel-Seeliger 則を使います。Lambert では低い太陽の平地が真っ暗になりますが、レゴリスは地平線近くでも平地が見えます。
- **空**: 真っ黒な空で、大気による散乱はありません。太陽円盤は地形や HLS に隠れれば見えなくなります。

## カメラ画像（レイトレーシング + 実機センサ風）

カメラ画像は、サーバ側（numpy, `lunarsim/raytrace.py`）で **画素ごとに光線を飛ばして** 生成します（`render: raytrace`、既定）。
HDR（線形・float16）で送り、ブラウザ側でセンサモデルを適用します。

- **一次光線**: 地形（高さマップのレイマーチング + 二分法）、岩（球）、HLS（円柱+上面）、地形の外側は平面。
- **影レイ**: 太陽方向へ判定します。
  地形自身は焼き込み済みのホライズン影、岩は球→地面の楕円影、HLS・ローバー（箱）は解析的な影レイで求めます。
  岩・HLS の表面には地形へのマーチング影レイを飛ばします。そのため、HLS の長い影やローバー自身の影が正確に落ちます。
- **反射**: Lommel-Seeliger 則。微小起伏と反射率のムラは周期ノイズで与え、遠方は LOD でぼかしてちらつきを抑えます。
- **空**: 太陽円盤（放射輝度 約4.7×10⁴）と、等級ベースの恒星（`stars`）です。
- **並列化**: 重い計算はワーカープロセスで実行します（`simulation.workers`、0 で CPU 数）。
  目安は 320×240 で 1 台あたり約 0.4 秒です。`rate_hz` は上限で、CPU が足りなければ下がります。
- `render: raster` にすると、従来のブラウザ側CG描画に戻せます（高速・近似）。`supersample: 2` で滑らかになりますが、約4倍遅くなります。

### 星は見えますか？
**日向に合わせた通常の露出では見えません。** 恒星の明るさを実際の等級から計算しているためです。
太陽は -26.7 等で、0 等の星は日向の地面の約10万分の1の明るさです。実機のカメラでも、月面を撮る露出では星は写りません。
空だけを見る・全体が影の中・露出を固定して大きく上げる、などの条件でだけ見えます（`exposure: 100000` 付近で微かに写ります）。
星の位置は合成カタログで、実在の星座ではありません。右の3Dビューの星は、雰囲気用の装飾です。

### センサモデル（`sensors.cameras[*]` で調整）
1. **露出**: 自動露出（空は除外、日向の明部が飽和しすぎないよう保護）か、固定倍率。`ev_bias` で補正できます。
2. **ノイズ**: 読み出し + ショットノイズ（`read_noise` / `shot_noise`）。影の中ほどノイズが目立ちます。
3. **周辺減光・光学ボケ**: `vignette` / `blur_px`。
4. **トーンカーブ → sRGB**。
5. **グレア**: 太陽が実際に見えている時だけ出ます（`glare`）。
6. **地面距離の目盛**: カメラ位置から、平坦な接地面を仮定した距離リング（既定 2〜50 m）を重ねます（`distance_overlay` / `overlay_distances`、画面の「距離目盛」で切替）。地形の凹凸の分だけ実距離とずれる推定値です。撮影時点のローバー姿勢で投影します。

右の3Dビューは見やすさのため、影の中の地形・岩にだけ弱い補助光（`ui.view_fill`、0 で無効）を足しています。HLS やローバーの影側は補助光を受けず、ほぼ真っ黒です（反射光は `world.sun.ambient` 程度）。この補助光はカメラ画像には影響しません。
HLS・ローバーなどの人工物は Lambert 反射、月面（地形・岩）は Lommel-Seeliger 反射です。

## 簡略化している点（今後の拡張候補）

- 特定地点の実DEM（LOLA 5 m・LROC SfS など）の読み込みは未実装です。GeoTIFFの取り込みを足せます。
- 永久影領域の暗さや地球照、太陽の時間変化（約29.5日周期）の自動進行は未実装です。方位はスライダで手動変更します。
- 地形外側は平面で、遠方の影はありません。
- HLS は円柱、ローバーは箱の簡易形状が既定です（`detailed` でも脚・エレベータは未モデル化。ハッチは描画のみ）。
- ローバーはキネマティクスのみです（スリップ・サスペンション動力学・轍は無し）。岩との衝突判定も無く、乗り越える扱いです。
